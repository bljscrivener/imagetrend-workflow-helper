# Routine A15 v0.2.0

This release replaces the separate procedure buttons and acknowledgment flows with a tabbed review panel. Install the full userscript from src/imagetrend-a15-helper.user.js on a15-mvp, save it in Tampermonkey, and refresh ImageTrend. The new @resource provides the approved clear-warning illustration; it does not receive chart data.

## Normal workflow

Open the helper. Its tab follows the active chart panel. **Scan this view** proposes local actions; **Chart → Review whole chart** visits recognizable sections and gathers one review plan. Select actions, acknowledge that they match the care provided, and apply. Unavailable sections remain explicitly blocked/manual rather than being declared complete.

The large Scan button starts yellow and turns green after a successful scan, or red on failure. Read timeline is at the far right, with yellow/green/red state. Timeline reading opens and closes the recognized right-side Times/Timeline toggle automatically; if already visible, the helper reads it without changing the user's open view. Missing navigation produces an actionable error. Timeline values remain in memory for the current chart for at most 15 minutes; observed edits, chart changes, and invalid input invalidate them.

Tabs: Chart, Treatment, Vitals, Transport, Delays, and Clear. Clicking a section tab uses recognized chart navigation. The panel is movable by its header, horizontally resizable, and minimizable. Log/testing controls are collapsed below the work area. There is one acknowledgment for the selected actions.

## Procedures

The Treatment scan offers a four-procedure bundle only for an empty visible procedure grid or a blank procedure entry. The bundle is unchecked until the user selects it. The review lists the planned timestamps:

- Assessment -ALS, Neurological assessment, Adult pain assessment: Arrived at Patient.
- Moving a patient to a stretcher: Depart Scene minus two minutes; if departure is unavailable, Arrived on Scene plus two minutes.

All four use Paramedic, prior-to-unit care No, protocol authorization, and successful Yes, subject to preserved conflicts. Timestamps are verified before Add Another/OK. No fallback to the current clock is used. Existing entries can receive reviewed timestamp corrections. Populated grids remain manual to avoid duplicate bundle creation.

## Vitals

From the multiple-vitals list, review/select sets and apply metadata. Inline entries are handled in place. Recognized modal entries are opened, read, and returned to the list automatically; accepted edits use the entry's native OK button. Measured numeric values are not written. Conflicting values remain unchanged.

An unrecognized row-edit handler blocks the operation with a request for the full list markup. This adapter has synthetic coverage but the actual user's multi-vitals row markup was not available for live verification.

ECG Not Applicable opens the field's minus-menu, clicks its exact special-value option, and verifies the selected value/watermark.

## Transport and delays

Hospital Team Activations offers an Add + No action only when its recognized list is empty. It creates one native inline entry and verifies No. No activation timestamp is invented.

Delay rules use exact field/option matches, tolerating only option capitalization:

- Unit Notified by Dispatch → Unit En Route: strictly more than 120 seconds → Staff delay.
- Scene delay remains manual, including scene durations greater than 20 minutes.
- Transport Delay → None, preserving conflicting entries.
- Arrived at Destination → Unit Back in Service: strictly more than 20 minutes → Documentation and ED crowding/transfer of care.

"Clear" time is mapped to the captured Unit Back in Service field (29342). Missing timeline sources do not create inferred delays. Unknown field labels/options require review rather than approximate matching. Updated source times are rechecked before applying a delay.

## Clear and testing

Clear defaults to selected values this helper added to previously blank fields during the current page run. Entries are identified by their generated procedure/vital key where available and must still match the recorded value. Open the relevant entry to make fields available. Measured vital numbers, original nonblank values, entire chart entries, and unrecognized clear controls are excluded.

The red button first displays the exact selected labels/values. The second, illustrated warning says **"This will nuke the selected chart data. You good with that?"** with Cancel and Yes, clear it. Both steps are required. A chart change or user-edited value prevents clearing.

Clear log removes displayed messages. Reset procedure test clears the current chart's retry lock after its own reminder; it does not remove chart data. Partial bundle failures keep their lock so the user must inspect earlier entries before retrying.

## Validation and limits

The suite covers option selection, timeline caching/navigation, threshold boundaries, procedure timestamps including midnight, role/default application, special values, activation creation, multiple inline/modal vitals, numeric preservation, clear provenance, and GUI confirmations/state. Run npm install, then npm test on a machine with Microsoft Edge; npm run check checks userscript syntax.

The source capture was inspected locally. Patient chart markup and screenshots are not committed. The popup art is generated, not patient data.

This release has not been validated on the live chart. Browser attachment was unavailable because the chart tab belongs to another active browser session. Navigation, grid edit handlers, and exact delay labels are detected at runtime and fail closed when unsupported. Chart Save/submit is never clicked, although native per-entry Add Another/OK accepts entries within ImageTrend.
